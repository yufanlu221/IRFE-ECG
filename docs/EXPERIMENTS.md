# Experiment guide

All formal suites use seeds 42, 43, and 44. `scripts/run_suite.py` rejects a
different seed set for versioned paper configurations.

Use a fresh environment without leftover `ECG_*` or `CPU_THREADS` overrides.
The launcher applies config values over the shell environment, but settings
not listed in a config still inherit shell values or module defaults. Its
`--dry-run` prints commands without training or checking data availability.

For a seed-42 smoke run, create `outputs/` if needed, then save the following as a local, untracked
`outputs/smoke_seed42.py` and run `python outputs/smoke_seed42.py` from the
repository root after data preparation. It uses the main configuration's
settings without changing the versioned seed list. It extracts seed-42
features and runs the primary routing job only; it is still a training run.

```python
import runpy
import sys
from pathlib import Path

suite = runpy.run_path("scripts/run_suite.py")
config = suite["_load_config"](Path("configs/main_routing.json"))
env = suite["_base_environment"](config)
suite["_validate_inputs"](env)
suite["_prepare_feature_cache"]({**config, "seeds": (42,)}, env, False)
job = next(job for job in config["jobs"] if job["name"] == "main_routers")
env.update(job["environment"])
env["ECG_SEED"] = "42"
env["ECG_OUTPUT_DIR"] = str(Path("outputs/smoke_seed42_main_routers").resolve())
suite["_run"]([sys.executable, "-m", job["module"]], env, False)
```

Stop here and inspect completion, split metadata, and validation-only
selection before starting the three-seed suites. Do not tune settings using
test metrics. Keep smoke outputs separate from the `paper` runs.

## Main routing

`configs/main_routing.json` first generates frozen ECGFounder features when
needed. It trains one balanced-softmax linear expert per source and evaluates a
pooled head, centroid, kNN, shrinkage-LDA, linear, and MLP routers. The same run
also reports hard MLP routing, top-2 validation-margin fusion, equal
probability averaging, and source-aware oracle selection.

## Robustness and memory

`configs/order_robustness.json` evaluates reverse and fixed-random source
orders. `configs/feature_memory.json` evaluates 1%, 5%, and 10% retained
feature fractions; the main configuration provides the 100% point.

| Setting | Fixed value |
|---|---|
| Main order | CPSC, PTB-XL, Georgia, Chapman |
| Reverse order | Chapman, Georgia, PTB-XL, CPSC |
| Fixed-random order | PTB-XL, CPSC, Chapman, Georgia |
| Expert epochs / primary learning rate | 30 / 0.0005 |
| Learned router epochs / learning rate | 50 / 0.001 |
| MLP hidden size / dropout / batch size | 128 / 0.10 / 512 |
| Small replay budget | 256 training ECG records per previous domain |

## References and ablations

`configs/shared_baselines.json` covers the shared linear head, full
fine-tuning, EWC, LwF, SI, and small replay. `configs/offline_reference.json`
trains matched independent heads with all source training sets available up
front. `configs/expert_loss_ablation.json` compares linear balanced softmax,
linear weighted cross-entropy, and a residual feature-adapter expert.

Run main routing before expert/loss ablations. That ablation loads the newest
matching main result for each seed across all tags under its results root;
keep only the intended main runs there. Its existing preflight checks the
paper's reference mean and standard deviation and stops if they differ.
Do not tune on test results to force this check to pass.

## Evaluation and publication artifacts

Training modules evaluate held-out test data and write `metrics_summary.json`
and related run artifacts; there is no separate required evaluation launcher.
The source-aware oracle requires the source identifier and is a reference,
not an autonomous deployment method. Any test-label-dependent oracle or
upper bound is non-deployable and must not guide model selection.

The README's three artifact commands use the output names generated by the
main, order-robustness, and memory configs with tag `paper`:

| Generator | Outputs / required inputs |
|---|---|
| `analyze_priority_router_results.py` | Main-run prediction-based confusions and paired bootstrap analysis; requires sample-level run artifacts |
| `generate_paper_router_artifacts.py` | Route-confusion figures/CSV, order-gap figures/CSV, memory-ablation CSV/TeX; requires routing run summaries |
| `generate_refined_ecg_figures.py` | Refined order and memory figures from run summaries; also requires the pooled-head runs |

The refined script's domain-gap panel and numeric caption text contain fixed
paper values. They are not recalculated for a different dataset or run.
`results/paper_tables/parameter_memory_accounting.csv` is a retained reference
table with no dedicated regeneration command in this release. The committed
`per_domain_oracle_gap.csv` is also a reference aggregate, not an output of
the three README commands under that filename. Preserve all reference files.

Shared-baseline and offline per-seed summaries can be collected after those
suites complete (Bash syntax):

```bash
python -m scripts.summarize_baseline_runs outputs \
  --out-csv outputs/baseline_summary.csv --out-md outputs/baseline_summary.md
```

This summarizer scans matching run folders under the supplied root; use a
clean output root for the intended run set. Expert/loss ablations write their
own `summary.csv` and `appendix_table.md`. New artifacts belong under
`outputs/`; do not overwrite the official reference results under `results/`.

Generated checkpoints, cached features, sample-level predictions, and logs are
written below ignored directories and are not publication artifacts.
